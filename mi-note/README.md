# 小米笔记（mi-note）

用二维码连接小米账号，并把小米云笔记镜像成本地 Markdown 文件夹，方便在 DSH 里整理工作规范、在手机上查阅。

## 在哪里

插件装好后有三处入口，它们是同一个页面：

1. 左侧边栏的 **小米笔记** 条目（在「上下文洞察」一带的导航列表里），点开在中间打开；
2. **设置 → 小米笔记**；
3. 装好后的一行插件配置（`mi-note`），配置项见下文。

## 怎么用

1. 在页面里点 **连接小米账号**，用手机上的「小米账号」App 扫描二维码并确认。
2. 连接成功后页面显示打码后的账号、连接时间和「可自动续期」状态。
3. 在 **笔记工作区** 里选一个绝对路径文件夹。这一项必须自己选：插件不会替你猜目录，页面给的建议是「文档\小米笔记」。选好后 DSH 会话的工作目录建议指向同一个文件夹。
4. 点 **拉取** 把云笔记写成本地 `.md`；点 **查看状态** 看每篇的处境；点 **预检** 看下一次推送会改什么（不写入）。

设置页只做只读动作。**推送和发布要从会话里让 Agent 调 `mi_note_sync` 执行**，因为那是会改云端内容的操作，需要你明确指定文件。

Agent 侧的工具 `mi_note_sync`：

| action | 作用 |
|---|---|
| `status` | 列出未变、本地已改、云端已改、两边都改、本地缺失、云端缺失、缺基线 |
| `preflight` | 只看不改：每篇计划做什么、格式会丢什么、绑定是否唯一 |
| `pull` | 把云笔记写成本地文件；可带 `path` / `noteId` 只处理一篇 |
| `push` | 把 `paths` 里指定的已关联文件推到云端 |
| `publish` | 为 `paths` 里还没有关联的文件创建云笔记 |
| `compare` | 取某一篇的本地、云端、上次同步三份正文，用于合并 |

## 推送的硬规则

- **只处理点名指定的文件。** `push` 与 `publish` 必须带 `paths`；不带就什么也不做，而不是「把所有改动都推上去」。
- **本地文件永不被覆盖。** 只有你明确 `pull` 且该文件未改过，云端内容才会落到磁盘。
- **冲突不猜。** 本地和云端都改过时报告冲突、保持两边原样；`push` 带 `resolve` 才会覆盖云端那一版，而这只应该在用户确认合并稿之后使用。
- **改名和移动沿用原笔记 ID。** 文件在资源管理器里改名或换目录后，插件按内容哈希找到原笔记；若同时有多篇内容相同的候选，列出候选让你选定，不会新建重复笔记。
- **本地删除只记状态。** 文件消失只标记「本地缺失」，本插件不会把云端笔记移进回收站。
- **结果不明先核对。** 创建请求超时或连接中断时，先重新读云端找那篇可能已创建成功的笔记；找不到就报「结果待核对」，不盲目重试。
- **单篇失败不影响其它篇。** 一批里逐篇报告成功、未变、冲突或失败。

## 正文格式的已知差异

小米笔记的正文不是标准 XML，而是「每行一个元素」的片段。平台本身没有代码块、表格、链接、H4 以下标题的标签，因此：

| 你的 Markdown | 到手机上会变成 |
|---|---|
| 代码围栏 | 普通段落（语言标识只作文字保留） |
| 表格 | 逐行段落，`|` 原样保留 |
| `[文字](链接)` | 纯文本，不可点击 |
| H4–H6 | 普通段落 |
| 独占一行的 `![图](minote://image/ID)` | 小米图片标签 |
| 段落中间的图片 | **不会**变成图片，预检会拦下 |

反方向（云端 → 本地）保留 H1–H3、有序/无序/复选框、引用、分割线、加粗/斜体/删除线/下划线、`<mark>` 高亮和图片引用；音频、视频没有附件登记表，会写成 `[附件：sound ID]` 这样的占位行，而不是被悄悄丢掉。

## 同步的底层约定

- 同一目录的写操作串行；映射文件与基线用「临时文件 + rename」原子替换。
- 云端列表没取全时整次操作不写任何文件，并报告原因，避免把「没取到」当成「云端已删除」。
- 文件名按 Windows 规则清洗（非法字符、保留名、重名加序号）；映射里记住的路径优先复用，所以同名不会每拉一次就多一份。云端目录名里的非法字符（例如 `a:b` → `a_b`）在推送时会映射回原目录，不会另建一个 `a_b`。
- 基线保存的就是磁盘上那份字节，因此「只改名、内容没动」的文件哈希不变，能被认成同一篇笔记。
- 推送成功后记录的是**实际提交的那一版**哈希；如果推送期间编辑器又保存了一次，新内容仍显示为待同步，不会被误当成已同步。

## 附带的小米笔记 Agent 预设

同一个 bundle 声明了名为「小米笔记」的会话预设（id `mi-note`）：人格提示词偏向规范整理与写作，工具是 DSH 原生的文件读写、文件搜索、待办与提问，加上插件提供的 `mi_note_sync`。新建会话时在预设里选它即可，规则与上面一致（先改本地、推送要指定文件、冲突不猜）。

## 账号与凭据

- 扫码、换票、续期全部由 Host 用 Node 的 HTTP 完成，**不启动浏览器、不读浏览器 Cookie**。
- `serviceToken`（分钟级）、`passToken`（长期）、`userId`、`deviceId` 保存在 **DSH 凭据库**的记录 `mi-note/account` 里，不写进任何配置文件。
- 笔记短令牌过期时，用长期令牌静默换票并重试一次；长期令牌被账号服务拒绝（例如返回 70016）时才需要重新扫码。
- 浏览器只收到二维码点阵、状态词和打码后的账号，收不到任何令牌、票据 URL 或原始响应。
- 断开连接会删除凭据记录并撤销在途任务，重启后维持断开。

## 配置项

在工作区 bundle 的 `cordis.patch.yml` 里，或由设置页写入：

| 键 | 含义 |
|---|---|
| `workspaceDir` | 笔记文件夹的绝对路径；空字符串表示「还没选」，此时拉取/推送/预检都会要求你先在设置页选择 |
| `mirrorDir` | 仅为兼容旧配置保留；`workspaceDir` 已配置时不再使用 |
| `defaultLimit` | 列表分页大小，默认 50 |
| `maxPages` | 最多翻多少页，默认 10；超出会明确报告列表不完整 |
| `timeoutMs` | 单次 HTTP 超时，默认 30000 |

## 关掉插件会怎样

不再发出任何请求，本地 `.md`、`.mi-note-map.json` 与 `.mi-note-baseline/` 都留在磁盘上。重新开启后凭据仍在，不需要重新扫码。
